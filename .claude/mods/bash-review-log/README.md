# bash-review-log

bash-review フック（Bash コマンドを実行前に審査する PreToolUse フック）の判定ログ
`~/.claude/logs/bash-review.log` を、ペインに一覧する Claude Code の mod です。

## 読み込み

`.claude/settings.json` の `env.CLAUDE_CODE_PLUGIN_DIRS` に `~/.claude/mods/bash-review-log` が入っていれば、
セッション開始時に読み込まれます。設定を変えたときは Claude Code を再起動してください。

## 使い方

```text
/bash-review-log                  直近 50 件を全種別で表示
/bash-review-log flagged          ASK・DENY・ERROR だけを表示
/bash-review-log deny ask 200     DENY と ASK を直近 200 件まで
/bash-review-log full             コマンドを折り返して全文表示
```

引数は順不同です。

| 引数                         | 意味                                                                             |
| ---------------------------- | -------------------------------------------------------------------------------- |
| `allow` `ask` `deny` `error` | 表示する種別。複数指定でき、省略すると全種別                                     |
| `all`                        | 全種別。ほかの種別と一緒に指定しても全種別になる                                 |
| `flagged`                    | ASK・DENY・ERROR をまとめて指定                                                  |
| 数字                         | 表示する件数（既定 50）。500 を超える値は 500 として扱い、0 は使い方の表示になる |
| `full` / `short`             | コマンドを折り返して全文表示する／1 行に切り詰める（既定）                       |

種別の ERROR は判定ではありません。Gemini か Codex が応答できなかったもので、reason に `gemini=ERROR` / `codex=ERROR` と出ます。

詳細ログのディレクトリが使えない実行 (`/tmp/claude_hooks` が他人所有・symlink・0700 に絞れない等) では、フックは詳細ログを止めてサマリーに `NOTE | logging | - | detail logging disabled: <理由>` を書きます (直近 100 行に既にあれば書かないので、続いても 100 行に 1 回程度)。これは判定ではないので、集計では ALLOW〜ERROR のどれにも入らず「その他」に数えます。この間のエントリは全文を引けません。

### ペインの操作

| キー     | 動作                                                 |
| -------- | ---------------------------------------------------- |
| `0`      | 全種別を表示                                         |
| `1`〜`4` | ALLOW・ASK・DENY・ERROR の表示を切り替える（複数可） |
| `w`      | コマンドの全文表示と 1 行表示を切り替える            |
| `r`      | ログを読み直す                                       |

- ペインを開いている間だけ、ログの更新を 2 秒ごとに拾って表示し直します。ペインを閉じると止まります。
- ペインにキーを渡すには `ctrl+x` → `Tab` を押します。
- マウスでボタンを押せるのはフルスクリーン表示のときだけです。tmux の中では既定で通常表示になります。
- 「閉じる」ボタンでペインを閉じます。
- ログを読めなかったときのメッセージには、ホームのユーザー名が入る絶対パスは出さず、`~/.claude/logs/bash-review.log` と書きます。

### 表示について

- サマリーログは 1 判定を 1 行に書きます。コマンドや理由に含まれる改行は `⏎` に置き換えられています。
  - 詳細ログ側のコマンドは実改行のままなので、照合するときに同じ置換を掛けます。
  - 改行をそのまま書いていた頃のログ（コマンドが次の行へ続く形）も読めます。
- サマリーログはコマンドを 80 字で切っています。
  - 全文は詳細ログ `/tmp/claude_hooks/logs/PreToolUse/Bash/bash-review/` から引きます。
  - 詳細ログは `/tmp` にあり、直近 1000 件までです。再起動より前のエントリは 80 字で切れたまま表示されます。
- サマリーの行と詳細ログは、行の末尾に書かれた詳細ログの名前で突き合わせます。
  - フックは、詳細ログを実際に書けた実行でだけ、サマリーの reason の末尾に ` detail=<詳細ログのファイル名>` を添えます。この名前は reason の末尾にあるものだけを数え、ペインの reason からは外して表示します。
  - 名前のある行は、その名前の詳細ログだけに対応づけます。その詳細ログが読めないとき（再起動で `/tmp` が消えた、読み込む範囲より古い、秘密検出で伏せてある など）や、コマンドの先頭 80 字が食い違うときは付けません。時刻での推定にも回しません。
- 名前の無い行は、書かれた時刻とコマンドで推定します。この形式より前のログと、詳細ログを止めていた・書けなかった実行の行です。
  - サマリーの時刻（ローカル時刻、秒単位）と詳細ログのファイルの更新時刻が近く、コマンドの先頭 80 字が同じものを対応づけます。名前のある行が指す詳細ログは、この推定の候補に入れません。
  - 決め手が無いときは付けません（別のコマンドの全文を見せるより、切れたままの方が安全です）。たとえば、同じ秒に同じ先頭の別コマンドが並列に走った場合や、片方の詳細ログが欠けている場合です。このときは全文も description も出ません。
  - 時刻はローカル時刻で突き合わせるので、Claude Code をフックと同じタイムゾーンで動かしている前提です。ずれていると、名前の無い行は全文を引けなくなります。
  - 書きかけで空や途中までだった詳細ログは、書き終わって大きさや更新時刻が変わったときに読み直します。
- 詳細ログの置き場は `/tmp` にあり、誰でも書き込めるので、次のものは読みません。
  - 置き場の各階層（`/tmp/claude_hooks` から `bash-review/` まで）が、自分の所有する実ディレクトリ（symlink でない）でないとき、1 本も読みません。ペインに「全文を引けません」と理由を出します。
  - 自分の所有でないファイル、通常ファイルでないもの（symlink・FIFO など）、256KiB を超えるもの。
  - 所有者と種別は `id -u` と `find`（`-user` `-type`）で確かめます。どちらもシェルを通さず、決まった引数で直接起動します。確かめられなければ（`find` が使えないなど）、詳細ログは読みません。
  - 読むときは先頭から 256KiB までの範囲で読みます。検査のあとに FIFO へ差し替えられても、範囲付きの読み出しは通常ファイル以外を拒むので塞がりません。検査と読み出しの間に差し替えられる余地（TOCTOU）は残ります。
  - 詳細ログの読み込みが 5 秒で終わらなければ、全文なしで表示します（ログ全体の読み込みは 9 秒で打ち切り）。
- ペインを描けない環境では、コマンドの返り値に一覧を載せます。
  - 載せるのは最大 20 件、サマリーの 80 字までです。
  - この一覧はモデルも読み、ほかのプロジェクトのコマンドも混じるので、詳細ログの全文は載せません。

## 開発

```bash
claude plugin test .claude/mods/bash-review-log       # テスト（ログの解析とコマンド・ペイン）
claude plugin validate .claude/mods/bash-review-log   # マニフェストとフックの検査
```

この mod はログを読んで見せるだけです。ツールの実行可否に関わるイベント（`tool.*` など）にはフックしません。
フックすると、bash-review や git-push-review を素通りさせる余地が生まれるためです。
一方で、`id` と `find`（詳細ログの所有者の検査）は Bash ツールを通さず、決まった引数でシェルを使わずに直接起動します。そのため、bash-review の審査の対象外です。
設計と安全上の前提は [docs/claude-architecture.md の「mod (関数フック)」](../../../docs/claude-architecture.md#mod-関数フック) にあります。
